# Portainer API spec taxonomy

Portainer publishes two editions (CE and EE) across two release streams (LTS and STS). This file maps every supported version to its specification file.

## Release stream model

| Stream | Cadence | Support window | Use case |
|---|---|---|---|
| **LTS** (Long Term Support) | Every 6 months | Until next LTS + 3mo migration | Stability, infrequent upgrades |
| **STS** (Short Term Support) | Monthly | Until next release | Latest features, frequent upgrades |

**Current supported releases** (as of Jul 2026):

| Release | Stream | Released | Support until |
|---|---|---|---|
| **2.39.x LTS** | LTS | Feb 2026 | Nov 2026 |
| **2.43.x STS** | STS | Jun 2026 | Jul 2026 |

**Recent past releases** (still relevant for deployed instances):

| Release | Stream | Released | Support ended |
|---|---|---|---|
| 2.33.x LTS | LTS | Aug 2025 | May 2026 (migration window until Aug 2026) |
| 2.42.x STS | STS | May 2026 | Jun 2026 |

## Spec files

All specs are raw OpenAPI 3.0 YAML downloaded from `https://api-docs.portainer.io/versions/`.

| File | Edition | Version | Stream | Operations |
|---|---|---|---|---|
| `ce-2.39-lts.yaml` | CE | 2.39.4 | LTS | 65 paths |
| `ce-2.43-sts.yaml` | CE | 2.43.0 | STS | 71 paths |
| `ee-2.39-lts.yaml` | EE | 2.39.4 | LTS | 120 paths |
| `ee-2.43-sts.yaml` | EE | 2.43.0 | STS | 136 paths |

CE specs are a subset of EE specs. The chunk-based spec in `../spec/` (generated by `make specs`) is EE-only at a fixed version — see `../spec/INDEX.md` header for which version.

## Edition surface differences

**EE-only API surface** (present in EE specs, absent from CE):

| Area | Paths |
|---|---|
| Backup (Azure, S3, local) | `/backup/*` |
| Cloud provisioning (AWS, Azure, GKE) | `/cloud/*` |
| Edge update schedules | `/edge_update_schedules/*` |
| GitOps (repo files, Helm values, refs) | `/gitops/repo/*` |
| LDAP (groups, test, users) | `/ldap/*` |
| Licensing | `/licenses/*` |
| Observability & alerting | `/observability/*` |
| Policies & recommendations | `/policies/*`, `/recommendations/*` |
| EE settings | `/settings/additional_functionality`, `/settings/default_registry`, `/settings/edge/mtls*`, `/settings/experimental` |
| SSH keygen | `/sshkeygen` |
| Support bundle | `/support/*` |
| Auto-updates | `/auto_updates` |

**Version-drifting surface** (present in 2.43 STS CE, absent from 2.39 LTS CE):

| Area | Paths |
|---|---|
| GitOps sources & workflows | `/gitops/sources/*`, `/gitops/workflows/*` |
| Endpoints summary | `/endpoints/summary` |
| OpenAMT (removed in 2.43) | `/open_amt` (2.39 only) |

## Resolution algorithm

When you need the right spec for a running Portainer instance:

1. **Get the version**: `GET /api/system/version` → `ServerVersion`
2. **Get the edition**: `GET /api/system/version` → `ServerEdition` (1 = CE, 2 = EE)
3. **Match the stream**:
   - If `ServerVersion` starts with `2.39.`, it's an LTS instance → use `*-2.39-lts.yaml`
   - If `ServerVersion` starts with `2.43.`, it's an STS instance → use `*-2.43-sts.yaml`
   - If `ServerVersion` starts with `2.33.`, it's a previous LTS instance → use `ce-2.33-lts.yaml` or `ee-2.33-lts.yaml`
   - If `ServerVersion` starts with `2.42.`, it's a previous STS instance → use `ce-2.42-sts.yaml` or `ee-2.42-sts.yaml`
   - For other versions, fall back to the official docs website (see *Fallback* below)
4. **Pick the edition file**: CE → `ce-*`, EE → `ee-*`

The bundled chunk spec (`../spec/`) may be from a different version than the target — always check the `INDEX.md` header. When in doubt, use the versioned full spec.

## Fallback: version not in taxonomy

If `ServerVersion` doesn't match any bundled spec (e.g. `2.45.0` after the next LTS release), download the exact version from the official Portainer docs site:

```bash
# Determine edition: CE or EE
EDITION="ce"  # or "ee"
VERSION="2.45.0"  # actual ServerVersion

curl -sSfLo /tmp/portainer-spec.yaml \
  "https://api-docs.portainer.io/versions/${EDITION}/${VERSION}.yaml"
```

The URL pattern is always:
```
https://api-docs.portainer.io/versions/{ce|ee}/{X.Y.Z}.yaml
```

This is the official, versioned, always-current source — no web search needed. If a spec for the exact patch isn't available, try the `.0` of the same minor (e.g. `2.45.0` → `2.45.0.yaml`).
